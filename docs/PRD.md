# AdPrompt Studio — 产品需求文档（PRD v1.0）

> 本文档按 Amplitude craft-spec 方法论编写：**先统一需求，再动手开发**。
> 阅读对象：产品 Owner（无开发背景）与执行者（工程师）。
> 状态：**✅ 已定稿（2026-08-19）**。需求已统一，开发已按本 PRD 完成至 D13；变更需 Owner 明示并更新本文档。

---

## 1. 问题陈述（Problem Statement）

**为谁解决什么问题：**

出海电商中小卖家（TikTok Shop / Amazon 卖家，无专业视频与设计团队）想为商品做广告素材，但：
- 不会写视频生成 prompt → 描述不清 → 生成不可控 → 反复抽卡浪费钱
- 不会提炼卖点 → 广告文案打动不了人
- 没有视觉方案 → 素材风格混乱、不统一
- 做完素材没有质检 → 凭感觉上线，效果不可控

**一句话：** 卖家"会卖货，但不会把货变成广告素材"。

**现状缺口：** 现有工具（即梦/可灵自带提示词优化）是通用对话式，不是面向卖家的结构化工作流，没有"卖点→文案→视觉→分镜→prompt→质检"的完整闭环。

---

## 2. 目标与成功指标（Goals & Success Metrics）

| 目标 | 成功指标（怎么衡量） |
|---|---|
| 让卖家 10 分钟内拿到一套可用广告素材包 | 生成成功率 ≥ 90%；质检通过率 ≥ 70% |
| 素材包可落地（文案能用、prompt 能生成） | 质检通过后复制率 ≥ 60%（主指标，用于 A/B） |
| 成本可负担 | 单次素材包生成成本 ≤ ¥0.5；全项目 API 总成本 ≤ ¥20 |
| 作品集价值 | 埋点 → SQL 漏斗/留存 → A/B 实验全流程有真实产出与结论 |

---

## 3. 范围（Scope）

### 3.1 产品定位（一句话）

**AdPrompt Studio = 面向出海电商卖家的广告素材生成智能体**：输入商品信息，一键产出「卖点分析 + 广告文案 + 视觉方案 + 分镜 + 多模型视频 prompt + 质检报告」的完整素材包。

### 3.2 v1 功能范围（本次要做的）

**核心工作流（P0，六步）**：

```
商品信息输入（名称 + 类目 + 描述）
   ↓ ① 卖点分析（AI 自动从描述提取 3-5 个核心卖点）
   ↓ ② 卖点→场景映射（每个卖点配 1 个使用场景）
   ↓ ③ 广告文案生成（按平台：TikTok 短视频文案 + Amazon 五点描述）
   ↓ ④ 视觉方案（风格/色板/构图文字方案 + 免费额度示例图 3-5 张）
   ↓ ⑤ 分镜 + 多模型 prompt（即梦/可灵/Seedance 2 三套模板）
   ↓ ⑥ LLM-as-judge 质检（风格匹配 + 可用性 2 维，< 3.5/5 自动重写 2 轮）
素材包输出（结构化 JSON + 可读 Markdown）
```

**平台适配（本次做）**：
- TikTok Shop：竖屏 9:16，短视频广告文案，15-30 秒分镜
- Amazon：主图视频 16:9，五点描述式文案

**数据验证闭环（P0，保持不变）**：
- 事件埋点（page_view / prompt_generate_click / generate_success/fail / quality_pass/fail / prompt_copy / feedback_good/bad / model_select）
- SQL 分析：激活漏斗（访问→生成→质检通过→复制）、留存 cohort、成本分析
- A/B 实验：质检后自动重写 vs 仅手动提示（主指标 = 质检通过后复制率）
- Streamlit 看板 3 张图（漏斗 / cohort 热力图 / 成本趋势）

### 3.3 明确不做（Out of Scope，v1 砍掉）

| 不做 | 原因 |
|---|---|
| 真实视频生成 | 成本高；本项目只生成 prompt，视频由用户粘到即梦/可灵自己跑 |
| VBench 自动化指标 | 2 周来不及 |
| 账号体系/登录 | 单机 demo 不需要 |
| 素材上传（用户自己的图片/视频文件） | 超出 MVP（注：已实现的"素材库"是**生成结果的历史记录**，不是用户文件上传） |
| 多语言（除中英 prompt） | 主战场中英够用 |
| Facebook/独立站模板 | v1 只做 TikTok + Amazon，后续可扩 |

> **2026-08-19 更新**：「历史记录」已从"不做"改为"已实现"（素材库，见 US-07）；「Prompt 优化模式」P1 已落地（US-08）。产品从单功能工具扩展为三视图产品（生成 / 优化 / 素材库）。

## 4. 方案概述（Proposed Solution）

### 4.1 技术栈（与交接书一致，不引 Dify）

| 用途 | 方案 |
|---|---|
| 工作流 | Python 脚本手写（六步管线，代码进 repo） |
| LLM | DeepSeek API（成本几元） |
| RAG | ChromaDB + bge-small-zh（本地免费，知识库 = D1 的 400 条 Seedance 范文） |
| 数据库 | SQLite（D1 已建 adprompt.db） |
| 前端/看板 | Streamlit |
| 埋点 | 自建 events 表（SQLite） |

### 4.2 数据资产（D1 已就绪，扩展后全部复用）

- **EAVSD 50 case**（400 场景分镜）→ 测试 case 与分镜参考
- **Seedance 400 条范文** → RAG 知识库（教 AI 什么是好 prompt）
- 新增：视觉风格参考（色板/构图规则，从 ecommerce-ad-creative-agent 流程沉淀为代码模板）

### 4.3 诚实边界（红线，与交接书一致）

1. 模拟数据带 `is_simulated` 字段，复盘报告写明「X 真实 + Y 模拟」
2. A/B 结论只标「方向性」+ 样本量局限
3. 不碰公司数据；成本透明，总成本 ≤ ¥20

## 5. 关键用户故事（Key User Stories + Gherkin 验收标准）

> 验收标准按 Gherkin 格式（Given-When-Then），每项都是可自动验证的验收测试。

### US-01 生成素材包（主流程，P0）
> 作为 TikTok Shop 卖家，我想输入商品信息后一键得到完整素材包，以便直接拿去生成视频素材。

```
场景：正常生成
  Given 我输入商品名称「YepCam X5 运动相机」、类目「3C数码」、描述（含防水/防抖/续航卖点）
  When 我点击「生成广告素材包」
  Then 系统在 60 秒内返回完整素材包
  And 素材包包含：卖点分析（3-5 条）+ TikTok 文案 + 视觉方案 + 分镜（6-8 镜头）+ 三模型 prompt + 质检分数
  And 生成记录写入 generations 表，事件 prompt_generate_success 落库

场景：输入为空
  Given 商品名称或描述为空
  When 我点击「生成广告素材包」
  Then 页面提示「请填写商品名称和描述」，不发起请求

场景：质检低分自动重写
  Given 生成结果质检分数 < 3.5
  When 质检器判定不通过
  Then 系统自动重写（最多 2 轮）
  And 每轮标注「第 N 轮」，最终返回最高分版本
```

### US-02 平台切换（P0）
> 作为同时做 TikTok 和 Amazon 的卖家，我想一键切换平台模板，以便两个平台各有一套适配素材。

```
场景：切换到 Amazon
  Given 我已完成一次素材包生成
  When 我选择「Amazon」
  Then 文案变为五点描述式（5 条 bullet）
  And 分镜适配主图视频（16:9），prompt 模板切换为 Amazon 风格
  And 事件 model_select 落库（platform=amazon）
```

### US-03 质检与重写（P0，A/B 实验载体）
> 作为卖家，我想知道生成结果是否达标，以便不上线劣质素材。

```
场景：质检打分展示
  Given 素材包已生成
  When 质检器打分
  Then 显示风格匹配分 + 可用性分（0-5）+ 总分 + 修改建议
  And 总分 < 3.5 时标注「质检未过」，≥ 3.5 时标注「质检通过」
  And 事件 quality_pass / quality_fail 落库
```

### US-04 复制与反馈（P0，埋点载体）
> 作为卖家，我想一键复制最终 prompt，以便粘到即梦/可灵生成。

```
场景：复制 Prompt
  Given 素材包展示完成
  When 我点击任一模型的「复制 Prompt」
  Then 剪贴板获得完整 prompt 文本
  And 事件 prompt_copy 落库（payload 含 user_id + product）

场景：点赞反馈
  Given 素材包展示完成
  When 我点击 👍 或 👎
  And 事件 feedback_good / feedback_bad 落库
```

### US-05 数据看板（Owner 审核载体，P0）
> 作为产品 Owner，我想看漏斗/留存/成本，以便判断产品健康度。

```
场景：打开看板
  Given 埋点数据已入库（模拟用户 is_simulated=1）
  When 我访问 /dashboard
  Then 看到激活漏斗（访问→点击→成功→质检通过→复制，含各层转化率）
  And 看到留存 cohort 热力图（D1/D3）
  And 看到成本趋势（每日成本 + 累计）
  And 页面标注「模拟数据，结论方向性」
```

### US-06 成本可视化（P1，面试加分）
> 作为产品 Owner，我想知道每个有效素材的成本，以便评估商业化可行性。

```
场景：成本展示
  Given 生成记录已入库
  When 我看板加载
  Then 显示估算总成本、单有效素材成本（总成本/质检通过数）
  And 标注「估算口径」（API usage 精确计量为迭代项）
```

### US-07 素材库（历史记录，2026-08-19 新增）
> 作为卖家，我想回看之前生成的素材包，以便复用和积累。

```
场景：查看素材库
  Given 我已生成过素材包
  When 我切换到「素材库」视图
  Then 看到历史素材包列表（商品名/类目/时间/质检分）
  And 点击某条可回看完整内容（卖点/文案/视觉/分镜/三模板）
  And 事件 library_open 落库

场景：复用历史素材
  Given 素材库列表展示中
  When 我点击某条素材
  Then 内容在生成视图完整渲染，可再次复制
```

### US-08 Prompt 优化模式（P1，2026-08-19 落地）
> 作为卖家，我想把效果差的 prompt 优化成好的，以便不浪费已花的生成成本。

```
场景：优化 prompt
  Given 我粘贴一个效果不佳的 prompt 并选目标模型
  When 我点击「优化 Prompt」
  Then 系统检索知识库最佳实践范文
  And 输出改进版 prompt + 改动清单（改了什么 + 为什么）
  And 事件 prompt_optimize_success 落库，记录存 optimizations 表

场景：空输入
  Given prompt 为空
  When 我点击「优化 Prompt」
  Then 提示「请粘贴要优化的 prompt」，不发起请求
```

### US-09 选品分析（V2 新业务域，2026-08-19）
> 作为卖家，我想先判断"这个品类值不值得做"，以便不把广告预算浪费在错品上。

```
场景：选品评估
  Given 我选择品类方向（或热门）与预算
  When 我点击「开始选品分析」
  Then 系统返回品类热度/预估毛利/平台合规要点
  And 按热度+利润排序推荐 SKU 方向
  And 事件 sourcing_success 落库
```

### US-10 素材导出与收藏（工作台能力，2026-08-19）
> 作为卖家，我想把素材包导出保存、把好素材收藏进知识库，以便积累和复用。

```
场景：导出素材包
  Given 素材库中有素材
  When 我点击某条素材的「导出」
  Then 下载该素材包的 Markdown 文件（含卖点/文案/视觉/分镜/三模板）
  And 事件 export_item 落库

场景：收藏到知识库（数据飞轮）
  Given 素材库中有素材
  When 我点击某条素材的「收藏」
  Then 该素材的三模型 prompt 存入 collected 表（用户验证过的"好 prompt"候选）
  And 事件 collect_to_kb 落库
```

## 6. 开放问题（Open Questions，需 Owner 拍板）

| # | 问题 | 决策（Owner 已拍板 2026-08-19） | 状态 |
|---|---|---|---|
| 1 | 卖点输入方式 | **AI 自动从商品描述提取**（多一步 LLM 调用，更炫；描述质量影响提取效果，已在提示词中要求结构化输出） | ✅ 已定 |
| 2 | 视觉方案深度 | **要 AI 生成示例图**。落地方式：文字方案为骨架（零成本），示例图用即梦/可灵**免费额度生成 3-5 张演示样例**，不每单出图（守住成本红线 ≤ ¥20） | ✅ 已定（折中方案） |
| 3 | A/B 实验方式 | 纯模型输出对比（自动重写 vs 手动提示），不涉及真实用户 | ✅ 默认 |
| 4 | 分镜输出格式 | 结构化 JSON（镜号/景别/运镜/画面/文案/时长），另附 Markdown 可读版 | ✅ 默认 |
| 5 | 质检维度 | **2 维**：风格匹配 + 可用性（阈值 3.5/5） | ✅ 已定 |

**决策记录：** 以上 5 项全部定死，开发期间不再改动；如需变更，Owner 明示并更新本表。
